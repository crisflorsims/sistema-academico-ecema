Análisis de la Clase 7: Módulo Unificado de Logística Aérea (MULA)

Este documento es una guía detallada y didáctica basada en el video de la "Clase 7", diseñada para que puedas dominar y enseñar el manejo del software MULA (Módulo Unificado de Logística Aérea).

1. ¿De qué se trata el sistema MULA?

El MULA es un sistema informático diseñado para la gestión, planificación y control de operaciones logísticas aéreas. Permite coordinar eficientemente el transporte de carga y pasajeros, asignar aeronaves, definir bases operativas y generar órdenes de tareas aéreas (ATO) y órdenes de tareas logísticas (LTO). El sistema está pensado para ser utilizado en simulaciones de juegos de guerra o ejercicios operativos militares.

2. Funcionamiento General

El sistema funciona bajo una arquitectura cliente-servidor y consta de dos componentes principales que interactúan entre sí:

  • Plataforma Web (Administración y Logística): Se accede mediante un navegador web. Aquí se gestionan los requerimientos (Requests), se organizan las terminales de carga, se manejan los manifiestos de pasajeros/carga y se visualiza el estado general de la operación.
  • Cliente de Escritorio (Planificación Aérea): Una aplicación instalable en Windows ("Cliente MULA") que incluye un mapa interactivo. En esta aplicación se planifican las misiones de vuelo (ATO), se definen las rutas (waypoints), altitudes y horarios de las aeronaves.

Ambos sistemas se sincronizan. Lo que se planifica en el cliente de escritorio (los vuelos) se refleja en la plataforma web para que el área de logística asigne la carga a esos vuelos.

3. Partes Principales del Sistema

Plataforma Web

  • Operation Admin (Administración de Operaciones):
    • Bases: Permite dar de alta, modificar o eliminar bases operativas (aeropuertos, helipuertos) definiendo sus coordenadas.
  • Air Logistic Control (Control Logístico Aéreo):
    • Requests (Requerimientos): Permite ingresar solicitudes de transporte (ej. alimentos, medicamentos, personal).
    • PLTO (Prioritized Transport List): Lista de transporte priorizada según rangos de tiempo (ej. Día D, D+1).
    • Air Freight Terminals (Terminales de Carga): Gestión de los paquetes que llegan a las terminales y creación de Manifiestos de Carga/Pasajeros para asignarlos a los vuelos.
  • Air Tasking:
    • Permite revisar las misiones actuales publicadas y su estado.

Cliente de Escritorio

  • Planning (Planificación):
    • New ATO (Nueva Orden de Tareas Aéreas): Creación de un bloque de planificación de misiones.
    • New Mission: Creación de misiones específicas (asignación de aeronave, base de salida, base de llegada, misión principal).
    • Navigation / Waypoints: Definición precisa de la ruta de vuelo, altitudes y tiempos estimados.

GeoServer (Servidor de Mapas)

  • Un servicio en segundo plano (requiere Java) que provee la cartografía y mapas base tanto para la web como para el cliente de escritorio.

4. Secuencia de Pasos para Ejecutar un Ejercicio Operativo

A continuación, se detalla el ciclo completo de una operación, dividiendo los roles para mayor claridad didáctica.

A. Preparación y Configuración (Rol Administrador / Técnico)

  1. Instalación del Cliente y Cartografía:
    • Descargar el instalador del Cliente desde la plataforma web (sección Downloads).
    • Instalar el archivo .exe.
    • Copiar la carpeta DATA (que contiene la cartografía) a la raíz del disco duro (ej. C:\Data).
    • En el cliente MULA, ir a System -> Settings y configurar el Data Path apuntando a C:\Data.
  2. Verificación del Servidor de Mapas:
    • Asegurarse de que GeoServer esté corriendo (ejecutando startup.bat). Si no corre, los mapas se verán en blanco.
  3. Configuración de la Operación en la Web:
    • El Administrador ingresa a la plataforma web.
    • Va a Operation Admin -> Bases y verifica o da de alta las bases operativas involucradas en el ejercicio, estableciendo sus coordenadas geográficas exactas.
    • En System Admin -> Time Ranges, define los rangos de tiempo del ejercicio (ej. Día D-1, Día D, Día D+1).

B. Gestión Logística (Rol Operador Logístico - Plataforma Web)

  1. Ingreso de Requerimientos:
    • Ir a Air Logistic Control -> Requests.
    • Crear nuevos requerimientos detallando qué se necesita transportar (carga o pasajeros), origen, destino y prioridad.
  2. Creación de la PLTO:
    • Ir a PLTO.
    • Generar la lista priorizada de transporte asignando los requerimientos a un rango de tiempo específico.
  3. Gestión en Terminales de Carga:
    • Ir a Air Freight Terminals y seleccionar la base específica (terminal).
    • Se verán los paquetes disponibles. Aquí se crean los Manifiestos.
    • Seleccionar los paquetes y asignarlos a un manifiesto, indicando que el material ya está listo en la terminal esperando vuelo.

C. Planificación Aérea (Rol Operador de Planificación - Cliente de Escritorio)

  1. Creación de la ATO (Air Tasking Order):
    • Abrir el Cliente MULA y loguearse.
    • Ir a la pestaña Planning, hacer clic derecho y seleccionar New ATO.
    • Definir el nombre y el rango horario de validez de esta orden.
  2. Planificación de Misiones:
    • Hacer clic derecho sobre la ATO recién creada y seleccionar New Mission.
    • Pestaña Main Data: Elegir el tipo de aeronave (ej. C-130), base de partida (Departure), base de destino (Final Arrival) y el Callsign (indicativo del vuelo).
    • Pestaña Navigation: Esta es la parte más crítica. Se deben añadir los puntos de ruta (Waypoints). Para cada punto se debe establecer la Altitud de vuelo (en nivel de vuelo / Flight Level) y los Horarios.
    • Nota didáctica: Si un avión va y vuelve por la misma ruta, asegurarse de asignar altitudes diferentes para la ida y la vuelta para evitar colisiones en la simulación.
  3. Validación y Publicación:
    • Guardar la misión.
    • Hacer clic derecho en la ATO y seleccionar Validate ATO. El sistema revisará que no haya errores (como cruces de horarios o aeronaves inexistentes).
    • Si la validación es correcta, hacer clic derecho y seleccionar Publish ATO. En este momento, los vuelos se envían al servidor y son visibles para el equipo de logística.

D. Ejecución y Enlace Final (Rol Conjunto Web-Cliente)

  1. Asignación Final (Web):
    • Con la ATO publicada, el Operador Logístico vuelve a la web (Air Logistic Control -> Air Freight Terminals).
    • Abre el Manifiesto previamente creado y ahora podrá asignar ese manifiesto a uno de los vuelos específicos que el Planificador acaba de publicar.
    • Cierra el manifiesto (el candado cambia a rojo), indicando que el avión ha sido cargado y está listo para despegar.
  2. Seguimiento:
    • Cualquier rol puede ir a Air Tasking -> Review current operation en la web para monitorear el progreso de los vuelos y el movimiento logístico en tiempo real.

5. Puntos Clave para la Docencia (Tips para el Instructor)

  • Sincronización: Enfatiza siempre a tus alumnos que MULA es un sistema de "esfuerzo combinado". La web (Logística) y el Cliente (Planificación) dependen uno del otro. Los logísticos no pueden cargar los aviones si los planificadores no publican la ATO, y los aviones volarán vacíos si logística no cierra los manifiestos.
  • Troubleshooting (Errores comunes):
    • El mapa se ve blanco: Recordar a los alumnos encender el GeoServer o verificar la ruta C:\Data.
    • No se puede publicar la ATO: Seguramente hay un error de validación en la pestaña "Navigation" (falta de altitud o incoherencia en los horarios).
  • Secuencia Lógica: Usa la analogía de una empresa de envíos. Primero el cliente pide el envío (Request), luego la caja llega al depósito (Terminal), se arma la hoja de ruta del camión (ATO/Missions en Cliente), se sube la caja al camión (Asignación de Manifiesto) y el camión sale (Review Operation).
